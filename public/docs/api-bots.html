01Como funciona

O bot é registrado como se fosse um agente de uma caixa de entrada. Toda mensagem que o cliente manda naquela caixa é enviada por POST para a URL do bot; o bot responde chamando a API de volta com o token dele. São dois canais de comunicação, em direções opostas.

Cliente Manda mensagem pelo WhatsApp, Instagram, Messenger, Telegram, e-mail, SMS ou chat do site
Arini Grava na conversa e faz POST assinado na sua URL X-Arini-Signature · timeout 10 s
Seu n8n Responde 2xx e processa o payload Webhook node · Respond Immediately
Seu n8n Chama /api/bot/v1/mensagens com o token do bot Authorization: Bearer …
Arini Entrega ao cliente pelo canal original e grava no histórico
DireçãoQuem chamaAutenticação
Arini → bot
recebe os eventos		 A Arini chama a outgoing_url cadastrada Header X-Arini-Signature — HMAC-SHA256 do corpo, com o secret
Bot → Arini
responde, transfere, etiqueta		 O bot chama /api/bot/v1/* Header Authorization: Bearer <token>

02Cadastro do bot

Feito pela diretoria da Arini em Atendimento › Configurações › Bots. O integrador não tem acesso a essa tela — peça o cadastro informando a URL do seu webhook.

CampoO que é
NomeIdentificação interna, ex.: “Bot n8n — Triagem”
URL do bot
outgoing_url		A URL do Webhook do n8n. Precisa ser https:// e pública
Caixa de entradaÉ o vínculo que faz as mensagens serem entregues. Uma caixa aceita um bot

Ao salvar, a tela devolve três coisas:

  • token — exibido uma única vez. É o que vai no Authorization: Bearer. O sistema guarda só o hash sha256; nem a Arini recupera depois.
  • secret — continua visível na tela do bot. Serve para você conferir a assinatura do que recebe.
  • bot_id — chega em todo evento no header X-Arini-Bot.
Comece por aqui

A tela de Bots tem um botão Testar: dispara um payload de exemplo, com a mesma forma e a mesma assinatura do evento real, e mostra o status HTTP e o tempo de resposta. Se o teste chega no n8n e a mensagem real não, o problema é vínculo de caixa ou estado da conversa — veja a seção 6.

O que nunca sai para o bot

Nota interna da equipe, o payload cru do provedor, tokens, segredos de canal e a ficha completa do lead (valores de negociação, anotações internas). É lista branca fechada.

Conferindo a assinatura

X-Arini-Signature é sha256= seguido do HMAC-SHA256 do corpo cru da requisição — o texto exatamente como chegou, antes de qualquer JSON.parse — usando o secret do bot como chave.

Node · Code node do n8n
const crypto = require("crypto");
const esperado = "sha256=" + crypto
  .createHmac("sha256", SECRET_DO_BOT)
  .update(corpoBruto)        // string crua, NÃO o objeto já parseado
  .digest("hex");
crypto.timingSafeEqual(Buffer.from(esperado), Buffer.from(headerRecebido));

No n8n, para ter o corpo cru é preciso ligar Options → Raw Body no node Webhook (o corpo chega em base64 na propriedade binária data). Sem isso, re-serializar o JSON funciona na maioria dos casos — o corpo é gerado com JSON.stringify e a ordem das chaves se mantém — mas não é garantido. Alternativa mais simples: usar uma URL de webhook com path aleatório e tratar a assinatura como conferência extra, não como única defesa.

Regras de entrega

  • Timeout de 10 segundos. Fluxo mais lento que isso conta como falha. Deixe o Webhook em Respond: Immediately sempre que o fluxo for longo.
  • 10 falhas seguidas desativam o bot automaticamente. O motivo fica em ultimo_erro, visível na tela de Bots; basta reativar depois de corrigir.
  • Toda tentativa vira log — payload, status HTTP, erro e duração. É por onde se prova “chegou / não chegou”.
  • Qualquer resposta 2xx é sucesso. O corpo da resposta é ignorado: o bot responde ao cliente pela API, não pelo retorno do webhook.

POST /api/bot/v1/mensagens

Responder ao cliente

Requisição
{
  "conversationId": "0f2b9d4e-1c3a-4b77-9f21-b0a5e6d84c10",
  "texto": "Olá, Gabriel! Sim, está disponível. Posso agendar uma visita?",
  "mediaUrl": null,
  "mediaTipo": null,
  "privada": false
}
CampoObrigatórioObservação
conversationIdsimO conversa.id do evento
textotexto ou mediaUrlTexto da resposta
mediaUrl—URL pública do arquivo
mediaTipo—imagem · audio · video · documento (padrão: documento)
privada—true grava nota interna — o cliente não vê e nada é enviado
Resposta
{ "ok": true, "mensagemId": "…", "entregue": true,
  "via": "evolution", "motivo": null }

entregue: false com motivo preenchido significa que a mensagem foi gravada no histórico mas o canal recusou o envio: número inválido, janela de 24 h da Meta fechada, canal desconectado. Nada some — o time enxerga a tentativa e o motivo.

Use privada: true para deixar contexto ao atendente que vai assumir: “cliente já informou o CPF”, “não entendi a intenção em 3 tentativas”.

POST /api/bot/v1/transferir

Passar para um humano

Requisição
{
  "conversationId": "0f2b9d4e-1c3a-4b77-9f21-b0a5e6d84c10",
  "motivo": "Cliente pediu falar com corretor",
  "equipeId": null,
  "agenteId": null
}

Três efeitos, nesta ordem:

  • bot_status vira transferida e o sistema para de entregar eventos ao bot nessa conversa — é a trava que impede o bot de falar por cima do atendente;
  • a conversa reabre (sai de resolvida ou adiada) e volta para a fila;
  • fica uma nota interna com o motivo, para o atendente entender por que a conversa caiu no colo dele.

equipeId e agenteId são opcionais: sem eles a conversa volta para a fila geral. Se o id não existir ou o agente não tiver acesso ao atendimento, a transferência acontece do mesmo jeito e o aviso vem em avisos[] — o essencial, sair do bot, não é desfeito por um id errado.

Sem volta automática

Devolver a conversa ao bot é ação manual, feita por uma pessoa no inbox. O cliente escrever de novo não reativa o bot.

POST /api/bot/v1/etiquetas

Classificar a conversa

Requisição
{
  "conversationId": "0f2b9d4e-1c3a-4b77-9f21-b0a5e6d84c10",
  "adicionar": ["locacao", "urgente"],
  "remover": ["sem_classificacao"]
}
  • Máximo 20 etiquetas por chamada, até 40 caracteres cada, sempre minúsculas.
  • Etiqueta nova entra automaticamente no catálogo, com cor neutra, para aparecer nos filtros do inbox.
  • Se a mesma etiqueta vier em adicionar e remover, remover ganha.

Resposta: { "ok": true, "etiquetas": ["locacao", "urgente"] }

GET /api/bot/v1/conversas/{id}

Ler o contexto

Devolve a conversa, o contato e as últimas 30 mensagens não internas, em ordem cronológica. É o que você usa para montar o histórico antes de chamar um LLM.

Resposta
{

  "conversa": { "id": "…", "canal": "whatsapp", "status": "aberta",

               "telefone": "+5534999998888", "email": null },

05Ciclo de vida do bot na conversa

O campo bot_status da conversa manda em tudo:

EstadoSignificaChega evento?
sem_botA caixa da conversa não tem bot ativonão
ativoO bot está conduzindosim
transferidaUm humano assumiu, ou o bot transferiunão
A regra que mais pega quem está integrando

A ativação acontece na criação da conversa. Conversas que já existiam antes de o bot ser vinculado à caixa continuam em sem_bot para sempre — elas não passam a disparar eventos.

Para testar, use um número ou contato que ainda não tenha conversa aberta, ou peça à Arini para resolver a conversa antiga antes.

06Não chega evento nenhum

Checklist na ordem do mais provável para o menos. As quatro primeiras causas acontecem antes de qualquer chamada de rede — nelas não existe nem tentativa registrada.

07Alternativa: webhooks de saída

Se a automação não precisa responder ao cliente — só quer ser avisada — existe um caminho mais simples, em Atendimento › Configurações › Webhooks: cadastra-se uma URL e escolhem-se os eventos.

EventoQuando dispara
conversa_criadaNasce uma conversa, em qualquer canal
conversa_atualizadaMuda status, responsável, prioridade
conversa_resolvidaA conversa é resolvida
mensagem_criadaQualquer mensagem, de entrada ou de saída — nota interna não
contato_criadoUm contato novo nasce pelo atendimento
JSON · corpo do webhook de saída
{
  "evento": "mensagem_criada",
  "enviado_em": "2026-09-09T19:41:07.512Z",
  "dados": {
    "conversa": {
      "id": "…", "canal": "whatsapp", "status": "aberta",
      "contato": { "id": "…", "nome": "Gabriel Souza",
                   "telefone": "+5534999998888" }
    },
    "mensagem": {
      "id": "…", "direcao": "in", "remetente": "cliente",
      "tipo": "texto", "texto": "…", "criada_em": "…"
    }
  }
}

Mesmas regras de assinatura (X-Arini-Signature), timeout de 10 s e desativação após 10 falhas. Headers: X-Arini-Signature e X-Arini-Evento.

Qual escolher

O webhook de saída avisa sobre tudo, mas não dá acesso à API de resposta. O Agent Bot recebe só a caixa dele e pode responder, transferir e etiquetar. Para um fluxo de atendimento no n8n, o Agent Bot é o caminho certo.

08Segurança

  • Guarde o token como senha — em credencial do n8n, nunca no corpo do fluxo.
  • Confira o X-Arini-Signature antes de agir no payload.
  • Use URL de webhook com path aleatório e não publique a URL.
  • Nunca devolva ao cliente conteúdo vindo de nota interna. O bot não a recebe, mas vale para o que o seu fluxo montar.
  • Responda 2xx rápido e processe depois.
  • Token comprometido: avise a Arini. O bot é desativado e recriado com token novo — não há rotação do token existente, por desenho.
Suporte

Para pedir o cadastro do bot, o vínculo com a caixa ou o log de entregas, fale com a equipe técnica da Arini. Para diagnosticar, tenha em mãos o nome do bot, o horário aproximado do teste e o número ou contato usado.
